## Deciziile agentului de migrare
| Subiect | Decizie | De ce |
|---|---|---|
| `valoare_lei` (§4) | privilegii de coloană: `authenticated` nu are SELECT/INSERT/UPDATE pe coloană; UI citește `red_v_parcele`; valoarea prin `fn_red_valoare_parcela` / `fn_red_valoare_parcela_seteaza` (admin) | mascare reală în BD, nu doar în UI; costul: `select=*` pe tabel pică (documentat în contract) |
| token de răspuns | tabel separat `red_detinatori_token` (Jakarinos r1 pct. 5), generat de trigger (`gen_random_bytes(32)` → base64url, 43 caractere), imutabil, SELECT doar admin/editor, fără scriere pentru nimeni | viewer-ul vede persoana, nu secretul; clientul nu poate impune un token slab |
| expirare token | `max(sesiune_zi1..3) + 30 zile`, 23:59:59 București; NULL (UAT fără zile) = nu expiră încă | convocatorul nu pleacă înaintea zilelor; recalcul prin trigger-e pe UAT / parcelă / deținător |
| rate limit | fereastră fixă 10 min în `red_rate_limit`; `ip:<ip>` max 30 (ambele RPC), `t:<sha256 token>` max 5 (doar la răspuns); tokenul nu e stocat în clar | afișarea formularului nu consumă din cele 5 trimiteri; tokenurile invalide consumă și ele (fără sondare) |
| jurnal | AFTER INSERT/UPDATE/DELETE pe 10 tabele; excluse `red_rate_limit` (contor anonim) și `red_detinatori_token` (secret); `valoare_lei` → `valoare_lei_setata`; rândurile de contact doar admin/editor; UPDATE care schimbă doar `updated_at` nu produce rând | jurnalul e proba față de Transgaz/APM, dar nu are voie să scurgă PII / secrete către viewer |
| `FARA_ADRESA_AFISARE` | și deținătorul fără rând de contact | nu are unde fi convocat |
| token expirat în RPC | același `token_invalid` ca inexistent (contract), cu contactul proiectului în răspuns | anti-enumerare |
| service_role | SELECT/INSERT/UPDATE pe tabele, ocolește RLS, dar `fn_red_nivel()` = NULL ⇒ numerotarea / valoarea îl refuză | edge-urile nu există încă; se deschide explicit când apare nevoia |
| bucket `redari` | privat, 25 MB, pdf / docx / jpeg / png; politici doar SELECT/INSERT/UPDATE pentru admin/editor | scanul PV semnat poate fi poză |

## Ce verifică migrarea singură
Precondiții: marcajul `gazpet.livrare_migrare = '20261126a_redari_teren:<txid>'`, `postgres`, nimic `red_*` / `fn_red_*` / bucket / politici
`red_storage_*` / cheia `redari` existente, `extensions.gen_random_bytes`, `auth.uid` / `auth.jwt`, rolurile, coloanele platformei, CHECK-ul
`user_module_access.access_level` cu admin/editor/viewer, RLS pe `storage.objects`.
Postcondiții: 13 tabele cu RLS + 4 vederi security_invoker (și nimic altceva `red_*`), 30 de politici (niciuna DELETE/ALL, toate
`TO authenticated`; pe jurnal / numere / token / rate_limit doar SELECT), anon fără niciun privilegiu, nimeni cu DELETE/TRUNCATE, jurnal fără
INSERT/UPDATE pentru roluri, `valoare_lei` fără privilegii pentru authenticated, tokenul izolat, indexul unic pe `cheie_sursa`, 10 trigger-e de
jurnal + 2 de imutabilitate, 19 funcții toate SECURITY DEFINER cu `search_path = public, pg_temp`, EXECUTE exact pe listele așteptate (anon
doar cele 2 RPC publice), controlul 0e echivalent (fără `set_config` / `request.jwt` / SQL dinamic / `set role` în funcțiile expuse), bucket
privat + exact 3 politici storage, cheia de modul fără niciun drept acordat.

  obiectele atinse (auth.*, profiles, app_modules, user_module_access, storage.*); diferențe posibile pe prod: trigger-ele proprii ale
  `storage.objects` (TEST8/TEST9 fac INSERT-uri care trebuie să pice pe RLS înainte), `postgres` fără superuser (local e superuser — dar
  testele de RLS rulează sub `SET LOCAL ROLE authenticated / anon`, deci echivalent).
- Concurența reală (două sesiuni) pe `fn_red_numar_document` / `fn_red_rezerva_numere_parcele` — doar raționament (UPDATE sub lock de rând).
- Performanța `red_v_stare_parcela` pe 2.728 parcele × deținători (subinterogări LATERAL + o funcție SECURITY DEFINER per rând);
  de măsurat după import, indexurile pe FK-uri există.
- Formatul exact `x-forwarded-for` trimis de PostgREST pe Supabase (se ia primul element din listă).
