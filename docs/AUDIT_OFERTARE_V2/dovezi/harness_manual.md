## 1. Cum se rulează

**Comandă**: `node scripts/audit-v2/scenarii/<pas>.mjs [--apply] [--dry-run] [--fixture <cale>] [--resume <checkpoint.json>]` (din rădăcina repo-ului; căile din fixture/`--fixture` sunt relative la cwd).
- Fără `--apply` = preview: tipărește contractul + configurația, **zero conexiuni**. `--dry-run` bate `--apply`. `--resume` doar la 16.
- **NU există `--faza`.** Fazele rulează în ordinea din `contracte.js` și lanțul se oprește (`break`) la prima fază neconfigurată sau cu verdict ≠ MATCH. Ex.: `03_cerinte` începe cu `extragere` (fără rețetă) → `confirmare_umana` nu e atinsă niciodată fără a configura manual `extragere`. Faze care blochează astfel: 03 `extragere`, 05 `motor`, 06 `revizie_F3` (a 2-a), 07 `editare`, 08 `generare`, 09 `verificare_finala` (imposibilă), 10 `asamblare` (a 3-a, imposibilă). Verdictul global = verdictul primei faze ≠ MATCH, altfel MATCH doar dacă TOATE fazele au rulat → scenariile cu faze `imposibil` (01, 09, 10, 11, 13–15) nu pot fi MATCH global; verdictele per fază rămân în `verdict.json`. Fix minim (nefăcut): un flag `--de-la <faza>` în `scenariu.mjs` (~3 linii).
- **Ordinea internă la `--apply`**: env → `citesteLicitatia` → `verificaSandbox` → snapshot BD complet (orice tabel necitit ⇒ abort „Precondiții necitite complet") → `verificaIds` D1/D6/D8 → precondiții MATCH → conectare CDP → `location.origin === app_url` → context UI → faze (fiecare: re-verificare sandbox + context, snapshot înainte, PNG, acțiuni, `asteapta` final, snapshot după, PNG, aserțiuni). Runner-ul **nu navighează niciodată**: pagina corectă trebuie deschisă de operator înainte.
- **Unde rulează**: `conecteaza()` acceptă doar `127.0.0.1/localhost/[::1]` și `DOM.setFileInputFiles` cere căi de pe hostul browserului ⇒ procesul Node rulează **pe PC-ul cu Edge (profil birou, CDP 9333)**, cu repo + `node_modules` (`@supabase/supabase-js`) acolo, Node ≥ 22 (folosește `WebSocket`/`fetch` globale). Din sesiunea cloud se lansează prin Desktop Commander `start_process`; nu direct.
- **Env (nume, fără valori)**: `SUPABASE_URL`, `SUPABASE_ANON_KEY` (= `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` ale aplicației, `src/lib/supabase.js`), `AUDIT_ACCESS_TOKEN` = JWT-ul de `access_token` al sesiunii `claude@gazpet.ro` (payload `role=authenticated`; service_role refuzat). Sursa: browserul autentificat — DevTools → Application → Local Storage → cheia `sb-dxczwkbciseqniprspcu-auth-token` → `access_token`; driverul nu îl citește singur. **Expiră în ~1 h**: reîmprospătează înaintea fiecărui scenariu. Opțional `prompt_env` (ex. `AUDIT_UI_PROMPT`) pentru dialoguri cu valoare sensibilă. Storage copy: `SUPABASE_URL`, `SUPABASE_KEY`. SQL local: `PGURI` (loopback), `PSQL_BIN`, `AUDIT_V2_RESPONSABIL_ID`.
- **Dovezi**: `docs/AUDIT_OFERTARE_V2/dovezi/<pas>/<ISO-timestamp>/`: `preconditii.json`, `N-<faza>-inainte.json/.png`, `N-<faza>-dupa.json`, `N-<faza>-dupa-<tab>.png`, `jurnal-<tab>.json` (fetch/XHR spre `*.supabase.co`: metodă, URL mascat, status, durată), `verdict.json`, `dupa-eroare.json` la eșec, `checkpoint.json` (16), `matrice-P4.json` (12). JSON > 2 MiB → `.0001.part…` + `.index.json` cu sha256. Exit code 2 dacă verdict ≠ MATCH.
- **CDP**: Edge pornit cu `--remote-debugging-port=9333` pe profilul autentificat. `cdp_target_id` = câmpul `id` al tabului din `http://127.0.0.1:9333/json/list` (`type:"page"`). Cu `cdp_target_id: null` trebuie să existe **exact un** tab de tip page, altfel „Selectează exact un tab". Contextul UI implicit: elementul cu textul exact `🏛 SANDBOX-V2-DOMNESTI` (antetul fișei, `OfertareLicitatii.jsx:3548`) — deci fișa clonei trebuie să fie deschisă. Pentru paginile cu selector de licitație se setează `context_ui` (§2).
- **Al doilea context (13–15)**: `cdp_port_2` (poate fi 9333) + `cdp_target_id_2` ≠ `cdp_target_id` (două taburi distincte pe aceeași origine, ambele pe clonă). Faza cere `pregatire`/`pregatire_2` (rulează în paralel, barieră) apoi `actiuni`/`actiuni_2` (lansate simultan). `scenarii.<pas>.obiect = {tabela, id}` trebuie să existe în snapshotul clonei.

`verificaSandbox(lic, fixture)`: `fixture.licitatie_id` întreg sigur > 0, **≠ 5**, egal cu `id`-ul rândului citit din BD, `nr_anunt` ~ `^SANDBOX-V2-.+` (case-sensitive). Concurență: `obiect.id` trebuie să existe în tabela clonei din snapshot. `caleSandbox`: Storage copy acceptă doar destinații `sandbox-v2/5/…` — **inconsistent cu clona executată** (obiectele reale sunt sub `103/atribuire/*` și `103/depus/*`, `p0_storage_103.md`); scriptul de copiere nu mai e utilizabil pentru 103 fără modificare (copierea s-a făcut deja pe altă cale).
Poate un scenariu scrie pe altă licitație? Harness-ul însuși este SELECT-only; scrierile sunt ale UI-ului. Garda verifică **ce licitație spune fixture-ul**, nu **ce atinge fiecare click**. Vectori reali: (a) `scrie` este permis pe `<select>` — un `scrie` pe selectul licitației (04/06/08) schimbă contextul după verificarea de la începutul fazei; (b) selectorii sunt liberi: un `text=`/`css=` care se rezolvă într-un control din lista de fundal (alte licitații) sau din alt tab; (c) aplicația este **producția** (`pontaj-pro-sooty.vercel.app` + BD live) — izolarea e doar pe rândurile cu `licitatie_id=103`; acțiunile UI ating și tabele globale: `ai_feedback` (Confirm/Corectez :2058), `notifications`, `ai_usage_log`, `ofertare_ingest_coada`/lansări + worker NAS + cost Anthropic (`☁️ Pe server`, `Propune acoperiri`), Edge live hardcodat `ofertare-verificare-finala` (:4646, cu parolă în prompt); (d) `📮 Marchează Depusă` scrie `ofertare_licitatii.status` doar pe fișa deschisă. Mitigări: nu folosi `scrie` pe selectul licitației; ancorează `css=` la `#acop-<id>`/selectul verificat; după fiecare fază caută în `jurnal-*.json` URL-uri cu `licitatie_id=eq.` ≠ 103 sau `id=eq.` în afara hărții clonei (parametrii de id nu sunt mascați).
